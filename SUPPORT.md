# Support

Thanks for using HostMK Security Framework. This document explains the expected support channels, maintenance expectations, and how to report product issues or security concerns responsibly.

## Supported versions

The project maintains support for the current release line and the active development branch. Older releases may be considered unsupported unless explicitly noted in a release announcement.

| Version / branch | Support status |
| --- | --- |
| latest release | ✅ supported |
| active main branch | ✅ supported |
| previous stable line | ⚠️ limited support |
| archival or legacy versions | ❌ unsupported |

## Support channels

### Community support

For questions, implementation guidance, and general project discussion, use the repository discussion and issue tracker:

- GitHub Issues
- GitHub Discussions
- pull request review and maintainer feedback

### Bug reports

Use the bug report issue template when describing a reproducible problem. Please include:

- affected version or commit
- environment details
- steps to reproduce
- expected behavior
- actual behavior
- logs or screenshots if relevant

### Feature requests

Feature requests are welcome when they align with the project’s scope and maintainability. Please open a feature request with a clear justification, expected impact, and examples when possible.

## Security reports

Security vulnerabilities must be reported privately and never as public issues. Please follow [SECURITY.md](SECURITY.md).

## Maintenance policy

The maintainers aim to respond to issues and pull requests in a timely and respectful manner. However, support response times may vary based on severity, scope, and maintainer availability.

The project follows a pragmatic maintenance model:

- open-source core components are maintained on a best-effort basis
- enterprise-only features remain subject to separate licensing and support arrangements
- documentation and governance changes are treated as part of project health and reliability
- security-related fixes are prioritized based on urgency and impact

## Response expectations

We aim to:

- acknowledge valid bug reports in a reasonable timeframe
- triage issues by severity and reproducibility
- provide clear guidance for fixes or workarounds when applicable
- keep the public issue tracker focused on actionable, user-facing concerns

## When to contact maintainers directly

Please contact maintainers directly only when:

- a support request concerns a private security issue
- a commercial or enterprise support request is required
- a legal, compliance, or licensing matter needs clarification

For licensing or commercial questions, use:

```text
contact@hostmk.com
```
